# 编码规范

## 概述

应用仓库维护规则，保证后续 AI agent 能快速理解当前代码库。只要改动会影响项目结构、运行方式或依赖契约，就把 `AGENTS.md` 当作必须同步维护的配套文档。

## 硬性规则

如果改动影响项目架构或依赖关系，必须在同一变更中更新 `AGENTS.md`。

不要只把架构或依赖变化留在代码、提交信息或 README diff 里。保持 `AGENTS.md` 最新，后续 agent 才不需要重新摸排整个仓库。

## 需要更新 AGENTS.md 的场景

- 新增、删除、重命名或重分配顶层包或重要子包职责。
- 修改实盘、GA、benchmark、报告生成或初始化流程的主入口。
- 在 `pyproject.toml` 中新增、删除、升降级、重新分类关键运行时依赖。
- 修改配置文件位置、必需的本地初始化步骤或环境假设。
- 新增共享的 agent 约定，例如新的说明文件或共享 skill 目录。

## 更新流程

1. 在修改可能影响结构或依赖的代码前，先读取当前 `AGENTS.md`。
2. 检查真正定义契约变化的文件，通常包括 `pyproject.toml`、`README.md`、入口模块和被移动的包路径。
3. 在同一组改动里更新 `AGENTS.md`，写清新的架构、命令、初始化步骤或依赖说明。
4. 保持描述事实化且简洁，只记录当前状态，不写猜测或迁移过程复盘。
5. 如果这次改动触发了规则，在最终总结里明确说明已同步更新 `AGENTS.md`。

## 约束

- 优先修改现有相关章节，不要在文末堆散乱补丁说明。
- 命令示例默认应能从仓库根目录直接运行。
- 依赖摘要必须与 `pyproject.toml` 保持一致。
- 说明文件和 skill 路径必须与仓库实际布局一致。
- 如果没有架构或依赖契约变化，不要无意义改动 `AGENTS.md`。

## 触发示例

- “把 factor benchmark 拆到新的顶层包里。”
- “把 `xtquant` 接入替换成新的券商 SDK。”
- “把实盘启动方式从 `python -m trading.main` 改成新的 CLI。”
- “把共享工具拆成新包，并同步修改导入路径。”
